# Unified organization next-stage feasibility proposal (U-D/U-H/U-S)

**Status:** CPU-authored proposal only; it authorizes no training, GPU reservation, or further U-specific GPU qualification.

The existing unified-organization implementation and its six one-epoch native engineering qualifications remain preserved as feasibility evidence, but no U arm has completed scientific fitting and no trained-U performance claim is available. The explicit current deferral supersedes the automatic-admission language in §8.5 of the [Round10 work plan](HONF_Round10_Continuous_Unified_Organization_Work_Plan.md) until the user separately authorizes a complete next stage.

## Decision and scientific questions

The proposed scientific scope is a Thermal-first matched U-D/U-H/U-S triplet, with a Wind triplet as an optional separately admitted part of the next stage. Each admitted dataset needs fixed TRAIN/DEV identity, exact source and recipe bindings, full horizons, and a separate final evaluation budget for every arm. The user may approve either complete triplet or both; no individual promising arm or partial qualification can substitute for its matched controls.

The questions are whether removing learned global summaries while retaining local input paths preserves useful field fidelity; whether continuous typed contextual gates in U-H and independent direct query gates in U-S produce different accuracy and executed work under matched conditions; whether the selected routes retain correct dense-reference values and derivatives through support changes; and whether any observed reduction in work translates into measured end-to-end time or memory savings.

U-D is the necessary all-open control under the same new local-input capability and initialization. U-H applies continuous typed incidence in contextual value updates and reuses continuous incidence for seeded query access. U-S uses the same contextual policy as U-H but has independently trained direct query gates. The mature dense arms remain useful historical context, but they are not the primary matched control because the new U capability deliberately removes summary broadcasts and changes the value-input contract.

A successful gate or smaller logical support does not establish lower native cost: report contextual edge work, decoder value rows, deduplicated native reads, fallback work, complete elapsed time, and peak memory separately. Learned support is not physical causality, geometry sensitivity is not a causal intervention, and model outputs do not establish valid generative designs.

## Future TRAIN/DEV protocol

Before any future authorization, freeze input-only TRAIN and DEV membership, the per-dataset manifests and fingerprints, train-only normalizers, source split, initialization, case and query sampling, objective, optimizer, schedule, and validation cadence. Use identical memberships, seeds, query draws, losses, and update budgets across each dataset’s three arms; choose cases from inputs only, never from targets, errors, or model-selected examples. Wind TEST remains locked and neither TEST partition may be used for tuning or model selection.

For Thermal development, the current default is the fixed stratified quarter-data protocol in the [Thermal development guide](../docs/guides/Thermal_Model_Development_Protocol.md): its fixed25_v1 manifest selects 150 of 600 TRAIN cases and 22 of 89 canonical DEV cases, with normalization fit only on selected TRAIN cases. The existing U recipes declare source_read_development_v1, but the e3000 parent checkpoint, membership and normalizer must be proven identical to the chosen fixed manifest before reuse; a mismatch requires a separately identified child and fresh forecast, not a silent relabel or resume. Reuse the existing Wind TRAIN72/DEV24 memberships, manifests, normalization and query schedule. Any proposed change needs its own explicit scientific identity and cannot be presented as a matched continuation of the existing panel.

The current U recipes target epoch 5000 from the shared epoch-3000 parent, a 2,000-epoch continuation per arm, with 100-epoch checkpoint reviews and 10-epoch curve refreshes. The cost estimate below applies only to those bound v8 recipes. If the next stage instead adopts the guide’s staged 100/500/1,000 development stops or changes panel membership, query budget, normalization, or horizon, write and price that different protocol before requesting authorization; do not combine its metrics with the current e3000-to-e5000 estimate.

## Correctness and evidence gates

Before fitting, bind the exact scientific v8 source closure, each parent checkpoint and recipe, dataset/provider identity, operation ledger, and future fixed TRAIN/DEV manifests. Verify that the local_records_context_v1 contract removes the declared global-summary and aggregated input paths while retaining the prescribed local and exogenous features, and poison target and unavailable-reference containers to confirm that preparation, route selection, and query selection do not read them.

Verify both contextual cycles in their actual MM→EM→EE→ME order: each exported incidence must be applied to that stage's donor values, with original record IDs and state/version provenance. Disable construction as well as application of the removed summary networks. Freeze the complete value plan, coefficients and normalizers for disconnected-component perturbation checks; then repeat with live routing to distinguish value paths from score/control dependencies. Test native E-conditioned M responses, local residual paths and conditioning sensitivity without adding capacity. U-D must agree with the new all-open U equations; equality to the old dense predictor is not expected after deliberately removing aggregate inputs.

Qualify the continuous math independently of training outcomes: compare the dense mathematical reference and packed executor on native value outputs and input/parameter VJPs/JVPs; include zero-support boundaries, ties, empty types, duplicate and permuted IDs, batch/chunk/repeated-query equivalence, zero-measure and padding cases, all-open recovery, and the declared local-envelope boundaries. Keep FP64 primitive references and FP32 native fitting separate, preserve all live gate derivatives, and reject an unsupported numerical mode rather than changing precision or weakening the acceptance envelope.

For legal geometry perturbations, rebuild provider scenes and derived local metadata for each side of every finite-difference pair, compare autodiff and finite differences only where the declared physical geometry remains differentiable, and separately label grid snapping or physical boundary crossings. Reuse all saved old seam coordinates and a fixed input-only set of candidate support transitions; report increment-versus-step curves, normalized and absolute units, derivative magnitude, and quiet-region/material/domain controls. Do not choose seams or validation cases from model errors.

After an authorized fit, report TRAIN and fixed DEV field metrics by field and relevant physical category, with sample counts and uncertainty appropriate to the panel. Compare all three U arms at the same retained checkpoints and choose best-field only from the declared 100-epoch monitoring grid. Report training fit, fixed DEV evaluation, and any representative field/graph exports as separate resource operations. A one-epoch cost receipt is not a substitute for full-horizon convergence, final DEV evaluation, or end-to-end executor measurement.

## Go/no-go gates

- **No-go now:** the user has deferred U training and further U-specific GPU qualifications; the dated saved estimates also exceed that snapshot’s update and non-evaluation slack.
- **Authorization gate:** obtain separate user authorization for the exact next-stage scientific scope, source lineage, data regime, full horizons, devices/resource policy, and final DEV evaluation; the old automatic rule cannot trigger work.
- **Identity and correctness gate:** freeze the six recipes and matching TRAIN/DEV manifests, validate source/checkpoint/normalization lineage, complete the source-isolation and continuous dense/packed forward-and-gradient checks, and qualify the legal geometry/seam procedures before any U GPU operation.
- **Complete-allocation gate:** reserve the entire U-D/U-H/U-S triplet for each dataset admitted to the next stage at its declared common horizon, plus full TRAIN/DEV evaluation, exports, engineering allowances, wall time and storage. Complete the current non-U campaign first. The user may approve Thermal, Wind or both as complete triplets; do not begin an arm because only its individual cost fits.
- **Execution and reporting gate:** preserve the exact recipes, 100-epoch checkpoint and 10-epoch curve cadence, full histories, and all-arm update counts; independently verify each final checkpoint and report fidelity, actual sparse work, fallback, full operation time, memory, fixed DEV metrics, and uncertainty. A failure or resource stop is reported as such; there is no automatic retry, extension, or next stage.

If the next-stage decision retains the original catastrophic guard, it must explicitly authorize and budget the missing 100-epoch gate-only boards, define the priority physical fields and require no same-field selected-TRAIN mean above twice same-age dense M at two adjacent saved e100 endpoints. The single retained e4900 observation cannot establish persistence or certify that guard. Ordinary +10% accuracy or measured speed/memory misses are reported outcomes, not replacements for the declared correctness, catastrophic or resource rules. All future thresholds must be fixed before inspecting new results.
