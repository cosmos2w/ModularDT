# HONF Round13-4 — Relation-guided original-member access

**Planning date:** 26 October 2026. **Scope:** improve the useful organization and physical-field reconstruction of the corrected Relative reader, using ThermalChannel as the current case adapter. This document specifies the next bounded research round; preparing it does not launch experiments or alter the independently authorized R13-3 continuation. Work in the current non-default branch of `cosmos2w/ModularDT`, inspect its live state, and preserve later user edits, historical loaders, checkpoints and active jobs.

## 1. The question and the progress to preserve

HONF learns relationships that participate in contextual information exchange and are reused to govern query access to original records. The corrected R13-3 model now has this complete trainable path: physically attributed M/E records → contextual exchange → reused directed relations B → query-dependent original-member reads → one joint physical-field predictor. Preserve that path. An organized read of an original member is the execution of routing; it is not a bypass. A query-dependent weighted reduction after member selection is legitimate. A shared pooled feature that replaces the members before query selection is a different model and is outside this round.

The [detailed Relative review and fixed-e500 supplement](../../../diagnostics/relative_organization_review_20261026/analysis.md#fixed-e500-reconstruction-and-organizer-comparison--26-october-2026) supplies the starting evidence. Continuous Relative improves all nine exposed-VAL89 mean errors by 53–72% from e100 to e500. At e500 it approximately matches Run1404 on u and improves on it in surface temperature, material temperature and interface q_proxy. The general joint predictor is learning useful physical information. Its relation rows have different scopes, and final member weights vary with query position. These are the foundations to develop, rather than reasons to restart with pooled group values.

The next question is specific: can those differentiated module views predict a sufficiently informative member subset before the expensive query–member MLP, while retaining broad cooperative relationships and improving reconstructed fields? Organizer utility and field accuracy are the primary objectives. Memory and latency are recorded as secondary objectives; an immediate exact algebraic saving is welcome, but a speed target must not drive premature loss of useful information.

## 3. Lessons that constrain the design

The fixed-zero-null double-entmax design allowed both typed reads to enter a dead region while the coordinate-conditioned output head continued reducing loss. Continuous relative preference and separately learned read strength repaired that failure. R13-4 must preserve their separation and real task feedback; it must not recreate an absolute-score competition against a fixed null at either selection level. A legitimate empty type at an individual query is allowed. Widespread disappearance of a previously active information path, with lost task sensitivity, requires immediate diagnosis.

R12-3 through R13 also exposed a conceptual failure: a query forced to reconstruct everything from pre-query averages or spatial coefficients turns organization into a compression bottleneck. Neither a merge tree nor a richer pooled basis is a substitute for learning who can access which original members and how. R13-4 may share indices, coalesce repeated member visits and use summaries as optional operations. It must retain individual IDs, positions, measures, prescribed controls and contextual values through the member read.

Do not respond to broad relations by forcing geometric neighborhoods, a target K, fixed top-k, a compulsory M/E winner, a delayed permission to reorganize, or a fixed early leaf period. Preserve the existing two-cycle MM→EM→EE→ME encoder initially. Exchange order, E→E removal and layer count remain later isolated questions; changing them together with retrieval would obscure this round's main comparison. M/E denote input-object roles, never separate output-physics responsibilities.

## 4. Baseline mathematics and the smallest useful change

For type t, retain the actual applied directory and the current physical information measure:

\[
B^M=G^{\mathrm{final}}_{MM,\mathrm{offdiag}}+I_M,\qquad B^E=G^{\mathrm{final}}_{ME},\qquad a_i^t(q)=\sum_m\pi_m(q)B^t_{mi},\qquad P_i^t(q)=\frac{a_i^t(q)\nu_i^t}{\sum_j a_j^t(q)\nu_j^t}.
\]

Here final ME means M receivers taking E donors; it is not evidence of a reverse exchange. Keep applied-stage provenance and live coefficients. An index may contain integer IDs, but its decoder weights must still connect to the applied relation tensors. The unmodified full reader forms conditional member preference p from P and the learned member scores, then computes c_t = rho_t sum_i p_i V_t(z_i). Rho remains separate from conditional preference and is not interpreted as calibrated physical importance.

When a type has no eligible positive path, return its genuine zero context before logarithms or normalization. The current M-address family also cannot route E in an M-empty scene. Preserve and test that declared limitation rather than silently adding an unorganized rescue path; adding environment-only address capability is outside this Thermal round.

Because every present M proposal is positive, the present exact-positive candidate union is the same union of B row supports for every q. The primary R13-4 change is to use the magnitude of P, rather than mere positivity, to choose candidates before evaluating the member MLP. For a declared conditional-prior omission tolerance epsilon_t, define C_t(q) as the shortest descending-P prefix satisfying:

\[
\sum_{i\notin C_t(q)}P_i^t(q)\leq\epsilon_t.
\]

Resolve equal weights by original ID. Deduplicate original members before scoring and reduction. This is a variable coverage decision, not a discovered group count. Epsilon = 0 is the full relation-eligible reference; a diffuse prior may legitimately retain the whole catalogue. Selection uses only the cheap relation composition and any explicitly declared lightweight refinement below, never hidden full member MLP scores. The first implementation may still compose and sort Q×E scalar priors. That cost is acceptable here and must be recorded honestly: the intended saving is avoiding expensive pairwise MLP work, not pretending that all query–member work disappears.

Retain M reads initially without candidate pruning: M is small, and restricting both types at once is unnecessary. First narrow E while preserving the learned optional typed read strengths and all M identities. This is an execution choice for the experiment, not a claim that M is always necessary or owns a particular physical output. Do not threshold rho to decide whether an entire type is worth learning.

Within C_E(q), execute the original-member reader and one joint head. Renormalizing the conditional distribution on C changes the function and can affect rho through its statistics; measure these changes. There is no extra unorganized full-E value path in the routed prediction. The all-eligible execution is a separately labelled reference and training comparison, not a hidden fallback added to an advertised sparse result. A deliberately broad candidate set reached through B is a valid result and must be counted as broad execution.

### 4.1 Repair the numerical reference without confusing different effects

For the new variant, make continuous all-eligible evaluation explicit and the default scientific reconstruction reference. Keep historical v2 loading and its historical defaults intact. Do not stack the old absolute-mass value truncation on the new early candidate mask during the primary comparison. If final-weight truncation is evaluated as a small no-fit diagnostic, express its omission relative to conditional p, report both conditional and rho-scaled mass, and retain the corresponding continuous result. Relative mass controls weight omission, not physical output error; value magnitudes and the nonlinear head still matter.

The current score mean/variance and entropy normalizer depend on exact-positive candidate count. A negligible coefficient can disappear and change other members' calibrated scores discontinuously. Reproduce the saved three-member arithmetic example and inspect the fixed TRAIN probes before changing the calibration. The preferred minimal correction, if carried into the new variant, is relation-weighted score statistics, with mu = sum_i P_i f_i and variance = sum_i P_i(f_i-mu)^2, retaining the unit variance floor and bounded tanh. Normalize entropy by the stable scene-eligible count rather than the changing count of positive coefficients. These statistics fade a vanishing-prior member continuously for finite scores; they do not remove the discontinuity of a deliberate hard candidate cut. For a restricted reader use P renormalized within its actual candidates and measure the difference from the full statistics. Computing all member scores to obtain a full mean/variance would defeat early selection and is prohibited in a claimed restricted execution.

Weighted calibration is a model change, not an exact optimization. If used, apply the identical calibration to both new comparison arms, report its immediate fixed-checkpoint effect against v2, and test native backward/response behavior. A focused counterexample or failed replay calls for correcting the formula, not launching a matrix of normalizers. Leave the calibration unchanged if the investigation justifies doing so; record the reason and the remaining boundary behavior. This decision is resolved once before the paired full-data experiment.

### 4.2 Teach the organization to anticipate useful member reads

A prior-mass prefix can be broad, or miss members whose final score strongly upweights a weak prior. Quantify both effects before adding a new selector. On a small fixed TRAIN query panel, compare P to the same model's all-eligible conditional p, measure the p mass captured by C, context differences, and native field differences. P coverage is not p coverage. With the existing bounded score range, even a small omitted prior mass can be amplified by the score likelihood ratio; do not present epsilon as a field-error certificate.

The first trainable Guide candidate uses the same encoder, applied B, proposal network, member values and joint head as the full reference. Optimize the existing native physical objective on both full and restricted executions of the same training queries, with their physical losses averaged. Tile or evaluate these paths sequentially rather than retaining duplicated full-query activations. Record the extra reference work. This directly asks the model to preserve physical information while making organization-controlled access useful, without forcing a sparsity count or adding another prediction head. Both paths use the same parameters; the full path is explicitly part of this bounded development objective, not part of the deployed routed prediction. Execute and measure the restricted path independently as well: it must not obtain hidden full-pass scores, statistics or pair tensors from the training reference. Scene-shared original-record projections remain legitimate reusable preparation.

If the measured relation prior remains poorly aligned with useful full-reader preferences, allow one small task-derived auxiliary term:

\[
\mathcal L_{\mathrm{guide}}=\frac{\mathcal L_{\mathrm{physical,full}}+\mathcal L_{\mathrm{physical,restricted}}}{2}+\lambda\,\mathbb E_{q,t}\operatorname{KL}\!\left(\operatorname{stopgrad}(p^{t,\mathrm{full}}(q))\,\Vert\,P^t(q)\right).
\]

Use only TRAIN queries and the live same-parameter full pass already being measured; do not create a frozen teacher, snapshot bank or external controller. The target is conditional preference, not rho-scaled weight, so reducing read amplitude cannot satisfy it. The term gives feedback to weak positive relations and proposals even when their members are excluded from the restricted physical path. It does not reopen an exact-zero B edge automatically. Observe actual gate/task gradients and contextual effects; never claim a derivative through a hard-zero gate that the code lacks.

This auxiliary term is retrieval prediction, not a demand that rows look different, local or sparse. Diffuse useful full-reader preference is an acceptable target. Use lambda = 0 initially; activate at most one documented nonzero setting after a short TRAIN gradient-scale and field replay, without a coefficient sweep. Retain it only if it improves captured useful reads or physical learning without disrupting contextual formation. Report both physical losses, the auxiliary loss and its gradient effect separately. Do not let agreement between two readers replace external field targets, and do not claim that attention weight is physical causality or unique member necessity.

### 4.3 Diagnose the granularity limit before adding capacity

The relation prior has a useful explicit form. With c_m^t = sum_i B_mi^t nu_i^t and normalized row R_mi^t = B_mi^t nu_i^t/c_m^t, it satisfies P_i^t = sum_m tilde_pi_m^t R_mi^t, where tilde_pi_m^t = pi_m c_m^t / sum_l pi_l c_l^t. Show pi and tilde_pi separately. Broad row mass currently affects address influence; do not silently replace this with a row-normalized mixture or label raw proposals as actual row contributions.

Use a small TRAIN-only projection diagnostic, capped at four input-selected scenes and eight fixed queries per scene: how well can a convex mixture of the existing normalized rows approximate the full-reader conditional preferences at different q? An optimized mixture in this diagnostic is an oracle expressivity check, not a deployed router or a new trained arm. Compare the actual mixture, the optimized mixture with its numerical residual reported, and full-reader p. An unrestricted simplex oracle is an optimistic bound for the row family: the bounded-score positive-softmax proposal may not realize its extreme mixtures. Distinguish that calibration/proposal constraint from a limitation of the B rows themselves. If the oracle works but actual proposals do not, inspect proposal scoring, temperature and row-mass effects before adding capacity; any chosen change is explicit, with no forced sharpening schedule. In the M1 case the unrefined prior is query independent by construction. These checks distinguish a proposal-learning problem from insufficient within-row query resolution. Do not spend many epochs asking an M1 proposal distribution to learn a choice it does not contain.

Only if that limitation materially affects candidate utility, replace the primary Guide candidate with one lightweight, relation-constrained refinement: R_i(q) proportional to P_i(q) exp(h(q,z_i)), on positive eligible B paths, followed by the same coverage prefix. Start with a normalized query/key dot product using existing routing features and one declared temperature; introduce a small learned projection only if those features demonstrably lack a compatible similarity. R replaces P as the cheap selection prior and as the optional auxiliary prediction target. It must remain much cheaper than the member MLP, retain live B dependence and original IDs, and report when it dominates rather than benefits from the relation prior. A dot product over all eligible E is still query–member computation; measure it.

This is a conditional alternative to the Guide candidate, not an automatic third full-data fit. It is especially relevant to M1 and broad overlapping rows. Do not instead add every original E as a mandatory new address, enforce local neighborhoods or introduce a hierarchy of pooled values. The evidence may also show that broad cooperation is genuinely needed; preserve that coverage rather than sharpening a plot for appearance.

### 4.4 Improve the predictor rather than only imitating its current reads

Treat the full-reader physical trajectory as an independent development target. Relative e500 has meaningful temperature reconstruction, while its v and p errors still leave a substantial gap to the historical references. Check native per-field loss scales, normalization, query/mask coverage, optimizer-state transfer and gradient contributions before attributing this gap to organization. Use the existing native losses and physical measures; correct a demonstrated implementation or scaling error coherently in both comparison arms. Do not optimize only aggregate loss or use dataset-specific output branches to conceal a weak quantity.

The joint head currently receives query coordinates and two query-weighted reductions of scene-shared values; relative geometry enters the weights, but not a query-conditioned member value. If correctly executed all-eligible reads keep missing resolved local detail, a natural next expressivity test is a small query-relative member message evaluated only after organization has selected its IDs. For example, replace V_t(z_i) with V_t(z_i) + h_t(z_i, q-x_i, prescribed member geometry) inside the same selected-member reduction and joint head. This retains member identity through query interaction and adds no independent value bypass. A residual message can begin function-preservingly with a zero output projection, while its output parameters receive task gradients immediately. Its additional memory and pair work must be measured.

This message refinement is a reserve mechanism, not an automatic decoder expansion or third full-data arm. First determine whether error comes from candidate omission, numerical calibration, ordinary ongoing learning, or an all-eligible representation limitation. If this becomes the strongest measured issue, test one minimal replacement within remaining qualification allowance and document why it takes priority over the lightweight selector alternative. Do not introduce both mechanisms together merely because they are available. A full 100-epoch branch comparison is followed by user review before further full-data candidates or extensions.

## 5. Strong, weak and overlapping relations

Retain all learned relation coefficients in the authoritative applied exchange. For indexing and inspection, expose strong and weak tails by cumulative relation mass, including their original IDs and distances. A weak long-range tail is not deleted merely because its geometric extent is large. The query-level coverage decision is temporary access selection; it does not rewrite the scene's learned graph.

Measure row overlap with support Jaccard and normalized-weight similarity, together with row mass and captured full-reader preference. Quantify shared members and address-specific residual members. Common members should be scored and gathered once per query, while their live coefficients accumulate from every contributing address. This exact overlap coalescing is the first reuse opportunity. If several rows share a large tail, they may share an index posting block with per-row coefficients; preserve their distinct module identities and relation views. Implement such a shared representation only if profiling identifies repeated expansion as material. Do not turn index sharing into feature pooling or declare highly overlapping physical modules redundant.

Use counterfactuals to ask what rows do: a decoder-only relation change holds contextual records fixed; an applied-exchange change recomputes every dependent contextual state and reuses that changed relation consistently. On a few TRAIN probes compare strong-only versus restored-tail access, actual versus row-mass-adjusted proposal contributions, and unchanged versus shuffled legal row assignments. Keep changed coefficients, candidate IDs, scores and actual execution explicit so a result can be attributed to a particular intervention. These are small no-fit diagnostics, not an ablation portfolio or evidence that a remote edge is physically causal.

## 7. Detect anomalies early and continue responsibly

Do not repeatedly restart an unexplained failure or deliver a failure report simply because the first trial missed a research metric. Conversely, do not promote an unresolved collapse to full TRAIN. After every fitting launch, delegate read-only monitoring to an explicitly selected Luna agent with a minimal handoff: exact owned run, epoch endpoint, logs, checkpoint paths, existing health/clean-stop signal and notification conditions. Luna stays quiet unless completion, failure, meaningful delay or user action requires notification; it cannot restart, extend or launch another job. The main agent does independent necessary work or waits, without duplicating log/GPU polling. Do not create a daemon, reservation layer or new monitoring framework.
