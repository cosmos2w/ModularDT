## 5. Design and execution questions that must be answered

### 5.1 Is selection learning exploiting a capable representation?

The root-versus-K32 gap is currently stronger evidence of a selector issue than a blanket statement that spatial functions cannot preserve detail. Determine whether the gap shrinks after development500 and full-data500. Count genuinely distinct case/node/action labels and compare covered versus undercovered bands. Head loss reduction alone is insufficient: prediction near zero can minimize regression error while choosing the wrong sign. Current labels use whole-case weighted native loss, so small regions or competing physical roles may have diluted/opposite advantages. Report those components before designing a local or role-balanced label.

One/two-level counterfactuals can miss a benefit that appears only after deeper subdivision. However, training a head on a K32 descendant target while inference executes only a binary split would itself be inconsistent. Any later deeper-utility design must align its supervised action with the actual deployed refinement or verify how deeper child decisions combine. Hard-coded fixed depths, desired K, validation-tuned margins and a confidence gate are not remedies.

The shared top-down utility function also ignores some surrounding-frontier context. Direct group attention changes its normalization when a group is split, so region gains need not be additive or purely local. Test the same selected node under at most two input-defined off-path covers on the four retained cases, rather than asserting globally optimal cuts. Do not build a generic planning/controller framework to answer this bounded question.

### 5.2 Do groups form useful information and retain module associations?

G1 and G2 share a partition/read primitive but are different evolving states. Measure the actual early group→M→stage2 dependence and its fieldwise utility after maturation; do not add an auxiliary loss to force the relay to matter. Relation scatter/discrepancy features are more informative than old symmetric row statistics, but their presence is not proof of useful relation-shaped subdivision. Separate organizer-feature ablation from removing module information in the physical encoder. If mature cuts remain relation-insensitive, report that explicitly instead of calling the geometry tree a learned physical hypergraph.

Exclusive connected groups, one shared cut across stages, first-order value modes and a mean-only key remain restrictions. A scene-level root with three modes can carry a useful global function without resolving localized peaks or source-specific response. Common-cover physical errors and latent fits distinguish insufficient value modes from poor query/key discrimination. Higher-order values, spatial keys, overlapping memberships, query-specific refinement and removing E→E are future hypotheses, not a list of new arms to implement here. Preserve the simple core unless mature evidence selects one bounded amendment.

### 5.3 Can the same mathematical model execute more economically?

The current code still copies E geometry to the CPU during preparation, computes all-node moments on both stages despite a known second-stage cut, retains diagnostic statistics, and uses per-scene loops and tiled read accounting. Investigate these specific sites with one warm substage profile at a mature endpoint; do not repeat cold traces and interpret their initialization overhead as a speed difference. Distinguish all-node policy statistics, selected coefficient formation, leaf transforms, retained E² attention, group reads, query/head work, extraction, paired backward and optimizer time.

Function-preserving batching, reuse of geometry-only cached metadata, selected-node-only second-stage statistics and deferring nonessential host counters are permissible optimizations when actual supported consumers permit them. Implement only a measured hotspot and keep diagnostic behavior available on demand. Validate same-checkpoint native outputs, relevant input/parameter gradients and one next-update/reload comparison on small M1/M12 cases, then report before/after complete runtime and peak memory. Do not cache graph-attached states across updates, omit P-mode costs or change precision/sampling to manufacture speed. These optimizations are not new scientific model arms and must not interrupt mandatory maturation unnecessarily.
