# Current HONF guides

Start here for everyday development. The top level contains five reusable guides; model-specific predecessor manuals and dated launch recipes are in the [reviewed archive](_bk/20261029_Guide_Consolidation/README.md). Historical usefulness is preserved without presenting old experiments as current instructions.

## Everyday references

| Guide | Use it for |
| --- | --- |
| [Global hypergraph organization visualization](Global_Hypergraph_Organization_Visualization.md) | The three standard global views, original-member semantics, matched examples and reusable plotting command. |
| [Thermal model development protocol](Thermal_Model_Development_Protocol.md) | Fixed input-stratified TRAIN150 membership, fair comparisons and ordinary qualification/evidence practice. Explicit user instructions and the current round's authorized budget take precedence. |
| [Run artifacts and monitoring](Run_Artifacts_and_Monitoring.md) | Maintained run folders, complete loss histories, selectors and compatibility with historical layouts. |
| [Thermal forward-run archive](Thermal_Forward_Run_Archive.md) | Locating historical baselines and preserved checkpoints; its dated inventories are not a live list of all current runs. |
| [Wind native catalogue cache](Wind_Native_Catalogue_Cache.md) | Reusing the existing Wind geometry catalogue with its native precision and safeguards. |

The repository [AGENTS.md](../../../AGENTS.md) governs architecture principles, storage, epochs, sparse Luna monitoring, authorized continuations and upload rules. A launch command in an old guide does not grant new training authorization.

## Current research and case entry points

The recent HONF direction keeps original M/E members, reuses actual contextual relations for access and integrates information after query participation. Current anchored A/L and module-mediated development are implemented in [anchored.py](../../src/honf_forward_core/interaction_reused_member_routing/anchored.py) and [mediated.py](../../src/honf_forward_core/interaction_reused_member_routing/mediated.py), with Thermal-owned adaptation in [member_routing.py](../../Case_ThermalChannel/src/channelthermal/member_routing.py). The research CLI is [honf_research.py](../../tools/honf_research.py). These pointers identify code ownership, not a claim that an experimental arm has passed its final comparison.

Use the [consolidated R13 report](../reports/HONF_R13_Consolidated_Work_Report.md) for the development history, the R13-5/R13-8/R13-11 milestones, measured evidence and current S/X formal candidates. Historical plans and reports are preserved in the [R13 archive](../reports/_bk/20261029_R13_Consolidation/README.md); their launch instructions do not grant new training authorization. The R13-12 module-mediated study is closed. Read literal checkpoints and completed-measurement labels rather than treating an old startup receipt as current progress.

For case-neutral core/case boundaries, consult [case_plugin.md](../case_plugin.md) and the [core README](../../src/honf_forward_core/README.md). For electro-thermal inputs and joint-field training, start with the [case handoff](../../Case_ElectroThermal/docs/COWORKER_HANDOFF.md). Wind-specific geometry remains owned by its adapter and the catalogue guide above; Thermal generation shortcuts do not define a general HONF predictor.
