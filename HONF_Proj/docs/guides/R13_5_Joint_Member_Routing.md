# R13-5 joint M/E member routing

R13-5 adds live environment (E) addresses and one typed joint member prefix to the existing interaction-reused reader. Its versioned core schema is `interaction_reused_joint_member_routing_v1`; the Thermal adapter and provider schemas are `thermal_interaction_reused_joint_member_routing_adapter_v1` and `thermal_joint_member_routing_provider_v1`. This guide describes implementation and maintained usage only; it reports no measured field-quality result.

## Applied relation directory

Preparation captures the final contextual cycle's actual applied directed blocks, indexed by typed receiver and donor inventories: `H_MM_applied` is M←M, `H_EM_applied` is E←M, `H_EE_applied` is E←E, and `H_ME_applied` is M←E. Their stage provenance and original destination/donor IDs remain attached to the prepared organization; these are stage-specific contextual relations, not a simultaneous influence matrix. In block matrix order with M rows/columns followed by E rows/columns, `H_exchange = [[G_MM, G_ME], [G_EM, G_EE]]` and `H = H_exchange + S_M`, where `S_M = diag(I_M, 0_E)`. The captured `G_EE` diagonal is preserved as applied, and no additional E identity is added.

For each scene, `μ` gives present M records equal discrete measure and positive E records their physical cell measure normalized to unit total within E; an absent role has zero measure. For each address row `a`, the core forms `r_a = Σ_i H_ai μ_i` and `R_ai = H_ai μ_i / r_a` when `r_a > 0`, otherwise zero. Thus μ is applied once and the complete concatenated M+E row is normalized once. Address proposals are `π_a ∝ ω_a exp(s_a/T)`, with `T=1` by default and a stable masked softmax. The base measure `ω` gives each eligible present address role total mass one: M addresses are equally weighted, while E addresses are weighted by their normalized positive physical measures. No across-role quota or score-variance scaling is applied.

Both address roles call the same `proposal_M` scorer with their own contextual keys and geometry; the E view adds no copied scorer parameters. `address_mode="M"` exposes M address rows only, while `address_mode="ME"` exposes both M and E address rows. Either view may retrieve original M and E members through its live H paths; an M-only address view does not force an M-only final read. The composed member prior is `P_i(q) = Σ_a π_a(q) R_ai`. Repeated paths to the same typed original ID therefore coalesce in its column before query-conditioned member scoring.

## Joint member selection and prediction

Restricted execution applies one shortest descending positive-mass prefix over the concatenated original-member `P(q)`, stopping when its cumulative prior reaches the configured `joint_member_coverage` (0.95 in the maintained R13-5 configs). The prefix is selected before the member MLP and query-specific value reductions. Ties use role order M then E and original integer ID, independent of padded slot order; the result is split into M and E candidate masks only after selection. Full execution reads all reachable eligible original members. Neither path uses pooling or forced role quotas.

For each retained role `t ∈ {M,E}`, normalize its prior over candidates to `P̄_i^t`, then apply the inherited prior-weighted calibration `z̃_i^t = 4 tanh((z_i^t − E_{P̄}[z^t]) / (4√(Var_{P̄}(z^t)+1)))` and preference `p_i^t = softmax_i(z̃_i^t + log P̄_i^t)`. Its independently learned typed gate contrast `d_t` gives `ρ_t = (1 + d_t/√(1+d_t²))/2`, followed by `β_i^t = ρ_t p_i^t` and `c_t = Σ_i β_i^t v_i^t`; an empty role has exactly zero context. The two contexts and query enter the existing shared joint field predictor `F(q,c_M,c_E)`. Pure-M, pure-E, and mixed joint95 reads are valid capabilities when live support and learned preference permit them; controlled synthetic tests establish capability only, while actual training occurrence must be reported from native traces.

Training evaluates both `read_execution("full")` and `read_execution("restricted")` from the same prepared scene and prescribed inputs. For each native field role, the task optimizes the arithmetic mean of its all-eligible and joint95 losses, with the existing physical role weights. The paired full path supplies task feedback for omitted members during training; deployment's restricted prediction uses only its joint95 candidates. Query-tile checkpoint recomputation captures the selected read mode so a later context-manager state cannot change the recomputed path.

## Traces and maintained commands

`JointMemberRoutingCore.from_config` and `validate_config` build and check the versioned core. `capture_interaction_routing_trace(prepared, query, intervention=None)` returns one bounded query trace (the query slice must not exceed `query_tile_size`). Stable trace families include `H_MM_applied`/`H_EM_applied`/`H_EE_applied`/`H_ME_applied`, `H`, `H_self_M`, route cycle/provenance and typed destination/donor IDs; `member_measure_joint`, `retrieval_row_mass`, `retrieval_R`, `prior_P`/`prior_P_uncut`; `proposal_scores_joint` with actual M and E slices, `address_weights`, role base measures and address block masses; `joint_candidate_mask`, `full_eligible_mask`, `candidate_ids_M`/`candidate_ids_E`; and per-role `prior_role_mass_*`, `retained_joint_mass_*`, `conditional_preference_*`, `member_read_strength_*`, and `member_weights_*`. Capture full and restricted traces in separate `read_execution` contexts when comparing the uncut role prior with the retained role mass. The optional `address_coverage` intervention is a no-fit query-dependent address cut; it is off by default and does not reduce address-scoring work already performed.

The qualification configs are `configs/research/thermal_r13_5_m_joint95_qual_train150_v1.json` and `configs/research/thermal_r13_5_me_joint95_qual_train150_v1.json`. The full-data development configs are `configs/research/thermal_r13_5_m_joint95_train600_development_v1.json` and `configs/research/thermal_r13_5_me_joint95_train600_development_v1.json`; both bind the literal R13-4 Guide epoch-500 checkpoint as their transfer source. The ME formal config, `configs/research/thermal_r13_5_me_joint95_train600_formal_v1.json`, starts fresh from the common seed-0 initialization with TRAIN600 normalization, declares a 500-epoch horizon, and begins with a 100-epoch segment.

From `HONF_Proj`, the maintained `train-member-routing` command starts an empty run directory; `--epochs` is the absolute endpoint in the configured lineage. Thus the R13-4 transfer configs reach absolute epoch 600 for 100 added epochs, while the formal scratch config's first segment ends at epoch 100. The transfer helper strictly checks the source arm/age, data bindings, TRAIN normalization, compatible model and optimizer inventories, schedule, sampler and batch packing; it preserves compatible model weights, named optimizer moments, RNG, sampler and provider clocks, adds no parameter, and resets the new health comparison origin. Here the historical source receipt identifies `cuda:1`, and the e501 transfer receipt maps RNG index 1 to target `cuda:0` index 0 while recording identical saved source streams; host RNGs and only the selected target CUDA stream are restored, with no claim for other visible streams or change to legacy exact resume. The formal scratch path does not inherit optimizer or model state.

```bash
python tools/honf_research.py train-member-routing \
  --config configs/research/thermal_r13_5_me_joint95_train600_formal_v1.json \
  --device cuda:0 --epochs 100 --output /data2/wanglz/ModularDT/round13_5_20261027/NEW_EMPTY_RUN_DIR
python tools/honf_research.py resume-member-routing \
  --run /data2/wanglz/ModularDT/round13_5_20261027/NEW_EMPTY_RUN_DIR \
  --device cuda:0 --stop-after-epoch 500
python tools/honf_research.py evaluate-joint-member-routing \
  --checkpoint /data2/wanglz/ModularDT/round13_5_20261027/NEW_EMPTY_RUN_DIR/checkpoints/epoch_0100_model.pt \
  --device cpu --output /data2/wanglz/ModularDT/round13_5_20261027/NEW_EVALUATION_DIR
```

Replace the illustrative DATA2 directory names with fresh paths that satisfy the saved config's storage budget. Resume advances the same run from its latest complete checkpoint and restores training state; it does not create a fresh lineage. `evaluate-joint-member-routing` evaluates both full and joint95 paths on canonical VAL89 and the fixed R13-5 detail panel. The source and config contracts are specified in the [Round13-5 work plan](../../UpgradePlan/HONF_Round13-5_Joint_ME_Organization_and_Member_Routing_Work_Plan.md).
