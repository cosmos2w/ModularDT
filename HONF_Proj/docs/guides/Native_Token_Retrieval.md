# Native-token retrieval over A2-D

The opt-in `native_retrieval_v1` family preserves individually identified contextualized module and environment records. Hyperedges contain native IDs, final-cycle MM/ME associations and routing permissions. They contain no pooled decoder value, prototype, moment bank or learned edge embedding. The primary decoder consumes module values only; environment membership is retrieval metadata and upstream context. Direct environment-value decoding requires a separate controlled architecture and pilot.

## Value and permission paths

`native_retrieval/core.py` derives from the maintained `ContentHypergraphCoreV2` A2-D core and retains every original parameter name. Last-cycle route capture is opt-in and leaves the existing SDPA contextual updates and historical EM/EE snapshot contract intact. Snapshots bind the actual stage, native IDs, allowed masks, owner, parameter and buffer versions, scene tensors, frame, normalization and policy. A token store or graph invalidated by input mutation, an optimizer update, changed thresholds or consumption by backward must be rebuilt.

Membership uses the relative density `exp(L - row_max(L))`, where `L` excludes log physical donor measure. The compact permission is `S5((relative - tau) / tau)`; `tau=0` explicitly opens every eligible route. Contextual MM excludes self, while retrieval adds each present module seed to its own member list. Preparation heads remain separate metadata; their conservative maximum is used for retrieval. This is a routing rule, not a physical influence coefficient or attention-error certificate.

Preparation associations describe their actual captured stage; decoder records use the final contextualized token states. A reused association is not a decomposition of those states’ complete residual ancestry. Max-product permissions are continuous and piecewise differentiable; competing maxima and rebuilt-support geometry transitions do not establish blanket smooth inverse readiness.

The query selector reuses A2-D's existing query/module scores. It unions selected native-seeded neighborhoods by maximum product and deduplicates `(batch, query, native module)` rows across seeds and heads. The existing compact local geometry window protects its original source IDs before applying physical measure. A selected row retains the original query-dependent Fourier geometry, SiLU message and output projection. Source IDs are correspondence labels and never numeric learned features. Cheap rectangular scores and union work remain part of the cost; this family does not claim sublinear source search.

Information attention normalizes permission times physical measure times the original score exponential. Thermal response instead contracts the signed, source-resolved coefficients with heating: `K_i = max_head(permission_i) * k_raw_i + K_local_i`. Information attention is not inserted into that sum. Heat does not select members or change contextual states, coefficients or flow. Native extraction, units, curl, q proxy and endpoint maxima remain owned by the existing case adapters. Wind keeps its nonlinear residual/profile transform and existing frame.

## Execution and counters

`selected` gathers original source coordinates and projections before evaluating the wide nonlinear values. Each unique admitted query/module row is evaluated once and shared across decoder heads. `dense_masked` is a same-permission reference that constructs the full rectangular Fourier/SiLU hidden tensor and then projects admitted rows. Its hidden-row count and message/scalar projection-row counts are therefore separate. The original full A2-D reader remains the complete dense application denominator.

`compiled_selected` is an explicit inference-only engineering option that fuses selected gather, Fourier/value evaluation and receiver reduction using the installed compiler. Every autograd-enabled call uses the faithful eager selected implementation, including training and native higher derivatives. Counters report the backend actually executed. Compilation/setup time is separate from warm complete-call latency. The Round7 report records its numerical and cost misses; availability of the option does not establish native qualification or a deployment recommendation.

The ordinary strength-zero route uses the original A2-D reader and recovers all eight fixed native TRAIN fixtures bitwise at unchanged source weights. A separate forced gathered all-open probe exceeds the strict native FP32 tolerance on several fixtures, even though the selected and dense-masked implementations agree at the same permissions. Those statements concern different comparisons. Neither gathered backend has a complete native deployment qualification from this round; the report retains the misses and the successful FP64 prepared-response algebra separately.

Trace requests can expose `native_seed_permission`, `native_module_permission`, selected batch/query/source indices and `native_selected_source_ids`. Counts distinguish rectangular score candidates, positive unique support, physically executed nonlinear hidden rows, output projection rows, padding, dense reference work and direct environment consumers. Environment metadata never increments consumed-E counts. An M-only reader rejects a plan claiming a direct environment consumer.

## Continuation identity

The primary experimental pair is conditional on the cost admission gate in the Round7 plan. Both arms branch from the exact retained D0 segmented e500 source and continue to absolute e2500 with named AdamW moments, the original LR schedule, initialization, case/query namespace, selected TRAIN membership, normalization, native losses, final partial optimizer batch and scheduled Thermal response. D-control retains the original reader without ordinary graph overhead. G-native-M trains all original parameters through its live permissions and native task losses; it adds no learned organizer parameters, teacher, completion path or auxiliary utility loss.

At e500 and e501 the ordinary function is the original all-open A2-D path. Routing strength is `(epoch - 501) / 499`, clamped to `[0,1]`, reaching the sealed thresholds at e1000. Every eighth absolute epoch from e1001 through e2000 replaces sparse access with one ordinary all-open epoch. Every epoch from e2001 through e2500 uses terminal compact permissions. An all-open call at adapted weights is not an accuracy fallback unless measured separately. Exact resume must restore the epoch, original sampling state and optimizer moments as well as weights.

The current Round7 study stops at its execution-opportunity gate; it does not contain mature matched trajectories or a direct-E pilot. See the [Round7 report](../reports/HONF_Native_Token_Retrieval_Round7_Report.md) for the measured evidence and limitations. Full-TRAIN fitting, TEST targets, inverse search and new physical solves are outside this family’s bounded round authorization.

## Library boundary

Construct a child from a maintained A2-D core with `NativeRetrievalCore.from_a2d(parent)`, imported from `honf_forward_core.native_retrieval.core`. This copies state by exact names and adds only the persisted `native_training_epoch` buffer. Dataset adapters and strict runtime loaders validate the explicit native schema; a source-read or moment/readout checkpoint is not silently relabelled as a native child. Use the registered runtime continuation path for experiments rather than creating another optimizer loop around this library boundary.

## Inert recipes and bounded execution

`tools/native_retrieval_train.py make-recipe --source-checkpoint <exact-D0-e500.pt> --treatment D-control|G-native-M --output <new-recipe.json>` seals the embedded source recipe, provider identity and checkpoint checksum. `prepare --recipe <recipe.json> --device cpu` validates the actual provider and original cadence without training. `fit --recipe <recipe.json> --device cpu --dry-run` checks the recipe without constructing the provider. These are preparation checks; they are not optimizer or native-field measurements.

A real `fit` requires an exact positive pair-admission receipt, its matching treatment recipe hash, the round-local storage and GPU budgets, `CUDA_VISIBLE_DEVICES` bound to the recorded physical GPU2 UUID, logical `--device cuda:0`, a distinct round-local `--output`, `--yes` and one of `--stop-after 600|1000|1500|2500`. A fresh child uses `--branch-from-checkpoint <exact-D0-e500.pt>`; later segments use the child's own `--resume latest`. The current negative Round7 admission receipt rejects both treatments before CUDA allocation or output creation. Changing a recipe or supplying metadata about E tokens cannot authorize an E-value reader.
