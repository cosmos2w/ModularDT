# Continuous unified preparation

The `unified_continuous_joint_native_v1` capability applies the same typed continuous incidence policy during contextual preparation and native query retrieval. It preserves original module/environment record axes, the two MM → EM(new M) → EE(new E) → ME(new E) cycles, local residuals/FFNs, native E-first decoding, signed source coefficients and case-owned physical readout. Implementation and software qualification are separate from the conditional Round10 training and its scientific conclusions.

## Inputs and initialization

`UnifiedJointCore.from_parent(dense_parent, input_dataset="thermal", routing_mode="hypergraph")` constructs U-H; use `direct` for U-S and `dense` for U-D. The input capability is `local_records_context_v1`. U-D/H/S use the same exact dense M+E e3000 parent. The local input transform intentionally changes the parent's mathematical function, so parent prediction equality is not asserted. Compatible common state is copied by name, and `parent_initialization_inventory` enumerates copied, fresh and dropped state plus the dropped named Adam entries.

Thermal's new transform zeroes the reserved E `nearest_module_distance_over_radius_minus_one` and `module_gaussian_occupancy` slots, and operating `module_count_over_12` and `module_count_per_domain_area` slots. Wind zeroes only `turbine_count_fraction`. Case-local `feature_contract()` exports the complete named feature inventory, retained/dropped channels and a canonical SHA256. The saved model config seals that hash. Frame/domain geometry, prescribed operating inputs, source identity, physical masks/measures, output scales and source/target construction retain their case definitions.

The unified model has no `scene_summary_net`, scene projections or scene broadcast gate parameters. Their outputs are never computed. Own-record raw skips and FFNs remain local value paths. Cheap dense scores, masks, native counts, measure normalization and external operating context remain declared control/exogenous paths.

## Applied exchanges

Before every contextual reduction, the actual stage raw scores determine a typed continuous incidence. The guarded measure-aware reduction computes only positive-incidence edge contributions from locally projected original records. No query/donor pair-value bank is constructed. U-D uses the original all-open SDPA kernel. The current capability requires the inherited zero dropout on both datasets. Output projection bias is weighted by mean per-head reduced message mass, so a zero donor path contributes exactly zero including its bias.

For native query retrieval, `native_backend` selects the H/S guarded value executor. The dense control executes the literal parent's `dense_ME` typed reader regardless of that sparse-executor option, while retaining the complete query-tile checkpoint. Its counters report dense executed rows, including padded rectangular rows; physical information eligibility and signed source presence keep their separate masks. The v8 source-correct dense mode supersedes v7's generic guarded-reader control, whose strict native FP32 physical parity failed. Strict actual-parent native CPU fields, losses and common gradients passed after the repair, and both dataset-specific fair dense controls completed four full native GPU epochs. The H/S guarded normalizer also uses the parent's raw measure weights with R=sum(r), S=sum(r*g) and Z=S/R; this preserves the real guarded equation while recovering the parent coefficients exactly at g=1. Positive-edge nonlinear values are still gathered before execution. Their weighted contributions enter a bounded query-tile scratch tensor and use the parent's original donor-order sum; scratch bytes and actual backend are charged separately from positive nonlinear rows. This restores strict native forced-open H/S parity on measured Thermal and Wind CPU fixtures without changing tolerances. Qt512 checkpointed H/S GPU cycles and the primary H40 lifetime run establish measured allocator feasibility for those execution settings; the near-open birth support does not establish learned sparsity, field accuracy or dense-relative memory savings.

U-H's final directory reuses the last cycle's actual applied b tensors. It does not recalibrate those scores afterward. Retrieval self-membership is restored separately from MM contextual self-exclusion. U-S shares the same upstream incidence parameterization while its query gates remain independent direct gates. Sparse context edge counts and decoder nonlinear value rows are distinct work measures.

The context controller has its own serialized `context` dual. Its retained-support target decreases from 0.98 at age 1 to 0.90 at age 1000, then remains 0.90. Observed positive support controls the dual; the differentiable support surrogate supplies gradient pressure. Per-case proxy/actual/eligible totals are reduced during preparation and passed through `JointMacroObjective` with the same equal-case macro arithmetic. U-D has no context penalty. Calibration must assign a justified positive initial dual weight or explicitly refuse an unsupported zero/nonfinite gradient; construction with an uncalibrated zero dual is preparation only.

## Provenance and interventions

Ordinary preparation exposes `context_stage_metadata` with real cycle/stage, source-state version, original typed IDs, ownership/scene bindings and eligible/positive edge counts. It stores compact per-case context work and the final directory required by U-H. It does not retain full eight-stage incidence/source snapshots as diagnostic traces. Explicit `return_trace=True` or `trace_request` enables `applied_context_stages` and `context_value_provenance`, bounded before execution by the trace element cap; use a small named scene panel. Decoder traces and frozen read plans additionally require a bounded native receiver panel with explicit IDs.

`capture_unified_context_plan(scene)` / `prepare_with_context_plan(scene, plan)` freeze all eight contextual exchanges, including complete coefficients, normalizers and applied incidences. Plans validate the model owner, parameter/buffer versions, scene frame, normalizer, original typed IDs and tensor versions. `capture_continuous_plan` / `decode_with_plan` separately freeze the decoder's continuous gates and E/M coefficients. Use both plans for whole-model diagnostic value-plane interventions. Live score/control dependencies may still propagate an omitted record's change in ordinary inference, because all-eligible score normalization remains live. A sparse value graph does not establish conditional independence or physical causality.

The public full-context plan supports FP32 U-D/U-H/U-S with different source-appropriate diagnostic representations. H/S freeze explicit continuous coefficients and normalizers. U-D freezes its actual scaled Q, normalized K and additive mask, then executes the unchanged SDPA kernel on fresh projected V. The earlier explicit-reduction U-D attempts failed rtol=2e-5, atol=2e-6 (3/24576 and 2/24576 E entries); those failures are retained and are not relabelled as passed. Same-kernel U-D replay now reproduces native Thermal TRAIN case 0581 (E192, named cells 0–2), prepared states and final fields bitwise under that same envelope. Ordinary U-D FP32 execution is unchanged. Capture defaults to a 500000-element plan limit; a named native U-D case can explicitly request `max_elements=1000000`, the hard maximum, to include all captured SDPA controls. Only opt-in diagnostic plans retain these tensors.

Software tests cover SDPA all-open outputs/gradients, empty donor behavior and projection bias; exact final-stage directory reuse; local input channel isolation and raw-scene freshness; Thermal zero-heat and source contraction; U-D/H/S standalone config/state roundtrip; context macro penalty/dual persistence; invalid capability declarations and feature hashes; compact ordinary versus bounded full provenance; and frozen full-context plus E/M/final-field component isolation. They do not establish field quality, continuity on the native physical panels, memory savings or completion of a training horizon.

## Sealed preparation and conditional execution

U-H/U-S inherit the same fixed TRAIN-only entmax temperature selected for their dataset's C-H/C-S pair. U-S binds its upstream contextual initialization to the exact matched U-H calibration receipt; direct retrieval gates are calibrated separately. Calibration records composed access, positive support and finite positive M/E/context gradient norms, restores model/provider/RNG/clocks and performs zero optimizer updates. U-D requires no routing calibration and drops only the eight declared summary state/Adam names from its common parent.

The maintained `continuous_joint_train.py` CLI supports plan, prepare, calibrate, qualify, fit, resume, status and standalone export. GPU qualification, fit and resume require `--source-manifest` and `--source-manifest-sha256`; the complete immutable repository inventory is validated before scientific imports and bound into the run identity. CPU preparation/calibration receipts identify their live, unsealed source and do not qualify a scientific epoch.

`continuous_unified_gate.py check --spec SPEC` consumes the root W6 hash-bound native board registry. Every saved 100-epoch age from 3100 through 5000 requires full selected-TRAIN physical boards for C-H and same-age D9-M on identical named receiver panels. A catastrophic failure requires the same priority field to exceed twice D9-M at both adjacent endpoints. Missing ages stay pending. The exact historical D9-M e3500 board may be reused through its bound checkpoint/panel certificate. The driver requires the literal C-H e5000 endpoint, software contracts, a complete reserved GPU native epoch for each U arm and a complete matched-triplet GPU/update/disk forecast before admission; incomplete evidence never passes. `run` then seals all three recipes and executes their complete horizons through the shared resource locks.
