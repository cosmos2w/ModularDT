# HONF interaction responses and inverse-design utility

## Physical question and scope

For a fixed set of heated modules in the ThermalChannel benchmark, which identified module-position changes jointly affect a named fluid-field, surface-flux, or solid-temperature receiver, and does that measured organization help choose a feasible position update? Heating, radii, module identities, and operating context stay fixed during the primary position task. The response-factor model predicts the *change* from an accepted baseline; it is a local model, not a cold-start absolute-field HONF replacement.

The reference in this study is the original ThermalChannel generator at `1_Demo_ChannelThermal/src/simulate_channelthermal.py`. It prescribes an analytic wake/pressure field and numerically advances a shared fluid/solid temperature grid with advection, diffusion, and heat generation. It is the independent generator of this dataset's labels, but it is explicitly **not** a Navier–Stokes CFD or high-fidelity conjugate solver. Generated responses can validate decisions only within this benchmark physics. The generator is a local ignored sibling of `HONF_Proj`, so an upstream checkout needs that local dependency to reproduce new reference solves.

The stored HDF5 physical solution is an exact-input baseline target. A frozen HONF checkpoint is a learned teacher. Analytic synthetic examples check algebra and information paths. The three sources remain separately labelled in records and results.

## Evidence design and numerical reliability

Each response record carries a physical family and split, original module IDs, design/context, perturbation, evidence source, solver settings/status, baseline and trial output roles, shared fluid query coordinates/mask/weights, module-attached port angles and solid coordinates, numerical uncertainty, and elapsed time. Eulerian field differences are formed only on a common fluid domain for the whole stencil. Port and solid differences use physical module ID and material coordinates. Unobserved or numerically unresolved labels are masked, not replaced by zero.

Before reading any new final-review response, the local split manifest fixed eight training, four response-calibration, and four new-layout final families, balanced over M=3/5/7/10. Each family has a geometry-selected two-module `3×3` position panel and two opposite `±0.125` heat transfers whose active-module total is conserved to float32 roundoff. The manifest records exact float32-rounded inputs, pair IDs/directions, step sizes (`0.075–0.15` dataset length units), and fixed pressure-section occupancy checks. The four generated final baseline signatures were screened against all 690 packed cases and each other with the declared `1e-6` input tolerance; none matched. The four calibration baselines come from the historical training split, so they test withheld response neighborhoods around teacher-seen layouts, not new composition. The frozen manifest and raw atlas remain local ignored artifacts.

## Anchored response-factor model

At one accepted baseline, physical donor set \(S_e\), receiver support \(\mathcal R_e\), output role \(t_e\), and validity neighborhood \(\mathcal U_e\) define a factor. Its order-one or order-two response is obtained by inclusion–exclusion from one shared decoder with identical cached baseline context and receiver support across every subset. Consequently every factor is zero if any of its own donor deltas is zero, and the total predicted change is zero at the baseline. A factor receives no delta for modules outside its donor set. The only path from a trial change to the predicted response is through these factors; no dense forward evaluation at the trial design is part of the response operator.

An exact-zero source retention score can skip factor decoding. Receiver localization is claimed only when supported by measured receiver responses; all-receiver support remains an explicit control. Counts of source factors, receiver incidence, and actual decoded work are reported separately. Offline support search uses training-family evidence only, then an input-only scorer predicts support from the accepted baseline. Its support is a decoder/evidence-dependent explanation, not unique microscopic causality.

The donor and score encoders see only their own donor tokens and prescribed operating context; material receiver heads can also see the queried receiver's baseline design token. The fixed reference baseline's *solved values* are used only as the output offset and for physical acceptance, not as model input features. The operator and scorer do not aggregate the positions/heating of *spectator* modules into a factor or support score. Thus a factor with the same donors and context cannot adapt its score to a changed third-party layout. This is a real conditional-organization limit of the current candidate, even though its trial information path is properly anchored. Adding a permutation-invariant baseline spectator summary is a possible next model remedy, subject to a fresh matched training/evaluation study; it is not claimed by the current checkpoint.

## Controlled inverse decision

The primary task minimizes a stable log-sum-exp approximation to peak *solid module* temperature while reporting the true peak and per-module peaks. The search temperature scale is predeclared as `τ=2.0` dataset temperature units: among the 510 historical HDF5 training cases with at least two active modules, the top-two module-peak gap had median `3.36883` (10th/90th percentiles `0.54932/8.85504`). The input heat scale is the training-only active-heat median `1.23906` dataset heat units. No calibration or final-review output set either scale. Feasibility requires the maintained inlet/outlet pressure-drop definition, disk/wall clearance, and a common normalized move radius. The graph-guided, size-matched random, and ungrouped policies share the same response operator, candidate count, inner effort, block dimension, radius, and reference-call budget. Each selected trial is accepted or rejected using an independent reference-generator solve; failed and rejected trials consume budget. Candidate ranking and finite-pool regret are reported only when every candidate in a clearly defined common pool has reference outcomes; a union of policy-specific evaluated proposals has a different interpretation.

A three-policy integration check on known training anchor `0001` executed one new independent reference solve per policy after GPU-2 surrogate scoring. All three converged in `2.839/2.757/2.747 s` of solver process time; this consumed three new physical solves and no final-review starts. The graph-guided and size-matched random selected moves were feasible but rejected after actual smooth-peak deterioration of `0.15234` and `0.000672`, respectively. The ungrouped selected move was feasible and accepted: smooth peak fell from `17.1038926` to `17.0636418`, while the true maximum was effectively unchanged (`18.8667679 → 18.8667374`). All three actual pressure drops stayed within the predeclared `1.05×` baseline benchmark limit. That run used an untrained response model whose predicted improvements were about `1e-6`, so it verifies the reference-acceptance mechanism only and establishes no graph utility.

The selected final-review manifest froze the **native Run 1511 decoder update 125 and scorer update 25** after the training-only support search and held response-calibration assessment. ## Results, resource accounting, and decision

The consolidated local physical-attempt ledger (`HONF_Proj/diagnostics/generated/interactions/physical_response_atlas_20260926/physical_attempt_ledger_all.jsonl`, ignored) now records **286 new solver attempts, all converged**: 17 initial pilot calls, five early pilot mesh checks, 176 core atlas calls, four `0333` mesh checks, three independent-heating null calls, three training-anchor inverse mechanism calls, and **78** selected final inverse/common-pool calls. The 78 divide exactly into 72 matched policy calls and six common-pool calls. The known per-solve process times sum to **1,281.2867 s** (`0.3559 h`), leaving 34 attempts under the 320-call ceiling and a large margin under the 24-process-hour ceiling. **Seventeen** calls lack a preserved per-solve process time: the seven earlier calls already disclosed and ten final M3 raw cases recovered after a ledger-serialization exception. Those ten completed physical solves were verified against their exact record IDs, finalized solver controls, layout, context, and converged output, then charged once to the ledger; a zero-solve GPU-2 replay rebuilt the invalid M3 decision trace before the full run continued. The interruption was an evaluator/ledger failure, not a failed physical solve or an extra free trial. Its missing times are not imputed. The selected inverse run's other 68 calls have `336.3785 s` measured solver process time. Stored HDF5 targets and reused final baselines are never counted as new solves.

The deployed graph requested `M+1` factors at each baseline (all unaries plus one scored pair) from capacities 6/15/28/55 at M3/5/7/10. It used all receivers and a 512-query decoder chunk. Across the four matched starts, the scorer evaluated 520 factor candidates, the response operator actually decoded 142 nonzero-donor factors, and measured cumulative scorer/baseline-preparation/decoder sections were `0.383/1.183/6.884 s` on GPU 2. The four complete matched-start wall sections were `27.67/69.90/90.26/144.41 s`; the M3 section is a **resume segment** and excludes the interrupted raw-solve period, so their sum is not the whole study's wall time. The separately frozen common pool used ten factor decodes and `0.295 s` decoder time. These sections are not a dense-model speed comparison; `K=M+1` is fixed cardinality, factor decoding uses all receivers, and reduction in candidate capacity does not establish sparse execution or speedup. The pair pressure increment in inverse scoring was fixed to zero under the generator's assumed analytic-wake additivity; it was not learned from a reliable pair-pressure label. The independent reference acceptance still used actual pressure for every trial.

**Decision:** this bounded candidate is **model-limited and scientifically inconclusive as a useful interaction graph**. The physical atlas contains measurable donor-set-to-receiver thermal interactions, but selected factors failed held finite-response adequacy, added spurious mixed response on the two matched new-layout pairs, and did not improve the four-start matched inverse decision consistently. The proper next experiment is a new, predeclared model/evidence round with spectator-layout conditioning, better unary response fit, a measured pair-pressure treatment or a constrained analytic convention, and receiver-support supervision where numerical floors permit. It should retain the matched reference-corrected inverse test and add targeted mesh checks of any promising decision; the present results do not justify an automatic 500- or 5,000-epoch continuation or a claim of mesh-stable physical design improvement. The local generator's analytic wake and interface-flux proxy remain hard fidelity limits; no external CFD validation was performed.
