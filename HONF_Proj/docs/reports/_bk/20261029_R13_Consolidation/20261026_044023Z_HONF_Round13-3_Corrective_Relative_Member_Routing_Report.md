# HONF R13-3 corrective result: relative original-member selection

ThermalChannel corrective round, 26 October 2026 UTC. The old reader lost final E reads and their native learning gradients early, then lost both final value paths in the historical TRAIN600 run. The replacement separates relative member preference from learned typed read strength, keeps the actual applied MM/EM/EE/ME contextual formation and live final MM/ME directory, and reads original records through one joint physical head. This is an implemented and trained correction, not another all-null endpoint review.

The corrected candidate completed 24 fixed TRAIN150 development epochs with an actual checkpoint resume, then one separately named scratch TRAIN600 lineage through epoch 100. It stopped there. [Every attempt and actual epochs](../../../../diagnostics/round13_3_20261025/corrective_20261026/attempt_ledger.json) and [Empirical selection and inherited resource forecast](../../../../diagnostics/round13_3_20261025/corrective_20261026/full_data_selection_and_forecast.json) retain the decision trail. No continuation after epoch 100, inverse fitting, response-fitting epochs, new solver calls or TEST evaluation occurred.

## What failed, and what the correction changes

The historical v1 reader used proposal entmax with a fixed-zero null, followed by member entmax with another fixed-zero null and additive log-address/log-measure priors. A common real-score shift can remove all real support despite unchanged rankings and positive applied B. In the exact-zero region, local selection derivatives vanish; evaluating more zero-weight values cannot reopen reading. The coordinate-conditioned joint head can continue reducing loss. The saved evidence establishes this inactive-path mechanism, not a uniquely identified initiating key/context drift.

Native diagnosis used the existing fixed TRAIN150 input strata 0006/M1, 0051/M2, 0322/M5 and 0231/M12, with the actual eight-role objective, fixed sampling and source checkpoint normalization. In M12, the member offset reopens native B/key/value feedback; in M1 it cannot repair an already closed proposal. Existing E priors are uniform-measure in E192, so disappearance cannot simply be attributed to a vanishing physical measure or lost IDs.

Historical U-H used entmax seeds without this appended double fixed-zero-null construction, live applied incidence composition, and a separate guarded measure-aware reader. Its observed local organization remains valid evidence for that historical checkpoint/backend. Its special Thermal heads and local envelope are not imported into this general joint predictor. R13-3 only reuses final-cycle MM/ME rows; it does not turn all upstream stages into one simultaneous causal adjacency.

The pre-implementation [corrective amendment](../../../../UpgradePlan/_bk/20261029_R13_Consolidation/20261026_032723Z_HONF_Round13-3_Relative_Selection_Corrective_Amendment.md) specifies the actual equations. On allowed candidates, `N(r)=4*tanh((r-mean(r))/(4*sqrt(var(r)+1)))`; query/key feature blocks use nonaffine LayerNorm for routing. Conditional M proposals are `pi=softmax(N(g)/T)`, with zero access when M is absent. Compose live `a_t=pi B_t`; normalize `P_t proportional to a_t*nu_t` within the eligible type, then use `p_t=softmax((N(f_t)+log(P_t))/T)`. Common score offsets and common within-type prior scales no longer become evidence that a type is irrelevant.

A small typed read/skip gate receives normalized q and relative score/entropy statistics, without an independent raw-control or record-value branch. Its contrast d gives `rho=(1+d/sqrt(1+d^2))/2`, evaluated with stable rational tails and derivative `1/(2*(1+d^2)^(3/2))`. Continuous training uses `w_t=rho_t*p_t` and the original values `c_t=sum_i w_ti*V_t(z_i)`. The existing joint head takes `[q,c_M,c_E]`. A nonzero gate derivative alone is insufficient: actual native dL/drho and organizer/value gradients are measured. Exact B zeros still have no fabricated local reopening gradient; other live contextual paths may change them, without guarantee.

Sparse inference keeps the shortest original-ID-stable descending-weight prefix with omitted absolute real mass at most 0.01 per query/type. It does not renormalize retained weights. A role can execute no values when its real mass is below that tolerance, independently of the other role. Training and sparse execution differ explicitly; there is no straight-through claim, forced nonempty read, top-K, support quota, epoch-triggered merger, raw-value rescue or pooled group-function bottleneck. The retained context error bound is omitted mass times the maximum original-value norm; physical output and response errors are measured after the nonlinear head.
