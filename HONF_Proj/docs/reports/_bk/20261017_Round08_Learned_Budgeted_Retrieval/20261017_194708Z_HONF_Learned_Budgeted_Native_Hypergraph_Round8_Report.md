## Execution: actual work and complete costs

The work objective counts the final union of dispatched members and protected exceptions. Its terminal target retains .60 of removable native rows above the input-derived floor `max(1, |P|)`. Native requests and query tiles are aggregated within a case before taking an equal-case mean; the augmented constraint uses the complete optimizer macro-batch residual. Birth membership is calibrated from fixed TRAIN inputs. A separately recorded TRAIN gradient calibration sets the initial work coefficient to approximately one tenth of the native routing task-gradient norm. No target, heat or native ID is a deployed routing feature.

The e501–700 phase uses binary stochastic forward routes with dense hard-forward routing gradients on every update. Later phases use that estimator every fourth global macro-step; other steps evaluate selected values with fixed-support task derivatives. The gradient is a biased training relaxation, not a derivative of discrete inference. Noise reaches zero at e1500. After e700, dual feedback uses observed deterministic work while sigmoid/softmax work remains explicitly a relaxation surrogate. No evaluation top-K is imposed to manufacture the requested budget.

Thermal has four updates per epoch. After e700, every-four cadence therefore always selects the six-case final partial macro for the dense routing step, including the original scheduled response call. Across the full continuation, dense steps cover 13.6% of primary case visits, rather than 25%; native auxiliary and response row counts are separate. Wind's five-update cadence rotates the dense position. Dense routing steps deliberately evaluate omitted values and are included in actual training work.
