# Source-conditioned fine core: Run 1507 specialization and bounded retraining

## Scope and evidence contract

This report follows `UpgradePlan/HONF_NextRound_Source_Conditioned_Core_Plan.md` on `agent/honf-core-next`. Run 1507 and its checkpoints remain historical artifacts. The 90 HDF5 `test` cases are development cases because the split was used for sampled validation; their full-grid errors are not untouched generalization estimates. Generated arrays, figures, and one-time evaluators remain under ignored `diagnostics/generated/` paths.

A CPU exact-array audit found one additional cross-split duplicate: train case 0001 and `test` case 0273 have identical stored steady fields, geometry, heating, interface targets, and all other compared physical arrays; their sampled-point arrays and case metadata differ. Across all 690 IDs, 31 pairs have identical steady-field arrays, but only this pair crosses the train/test split. Full-90 tables retain the repository's established cohort; any new physical conclusion also reports an 89-case sensitivity excluding 0273. Neither cohort is an untouched test set.

The static `source_conditioned_pairwise_honf` reader specializes the *observed all-closed* Run 1507 operation. It keeps the K=12 source organizer, provisional \(\pi\) and \(\kappa\), fine physical module and environmental sources, source-conditioned gains, global context, and the P0/P1/P2 port and local-surrogate loop. It removes the tree controller and query-to-group access functions. For each valid physical source \(s\), the prepared controls are \(u_s=\sum_k A_{sk}h_k\), \(r_s=\sum_k A_{sk}/K_{\mathrm{active}}\), and \(n_s=u_s/K_{\mathrm{active}}\). The all-occupied Run 1507 e500 reference has \(K_{\mathrm{active}}=12\). The new reader prepares QM gain once per module, applies QE value gain from unscaled \(u\), folds QE score gain from \(n\) into projected keys, and retains output biases and inherited \(\kappa\) calibration.

Logical R=1 is one query-access class, not one physical source. The fine QE rectangle remains 192 valid environmental sources on the reviewed cases. At Q8192, each P2 field read executes 1,572,864 query-environment geometry rows and 6,291,456 headwise content-dot rows with four heads. No fine-pair sparsity or physical-causality claim follows from this algebra.

## Source-control and physical-risk diagnosis

The saved e500 source maps are not featureless despite the root closure. In three representative P2 cases, 0273/0647/0686, all 12 proposals are occupied, while each environmental source has nonzero membership in about 2.42/2.44/2.61 proposals on average. The inherited \(\kappa\) is 9.713/10.347/11.801. RMS deviations of the prepared QM, QE-score, and QE-value gains from identity are respectively 0.084/0.054/0.845 for case 0273, 0.080/0.053/0.845 for case 0647, and 0.091/0.060/0.889 for case 0686. These are measured source-side states, not a target-based estimate of usefulness. Sparse proposal membership does not reduce the 192 physical QE source rows per query in the current operator.

The ignored local figure `diagnostics/generated/stage_a_source_core/source_conditioned_static_core/run1507_e500_source_conditioned_static_core.pdf` shows the measured P2 incidence, source-local controls, and gain variation for M=3 and M=10. Its right panel keeps the original uniform-\(\alpha\) closed-route equivalence separate from the static backend, which has no query-route tensor. At Q8192 the M=3/M=10 physical QM rows are 24,576/81,920, and both have 1,572,864 QE geometry rows plus 6,291,456 four-head content-dot rows. These are arithmetic work counts, not latency estimates. The local figure and its arrays are intentionally excluded from Git.

The inherited training objective already supervises final T ports: effective port-supervised weight 0.3, a squared T error scaled by 10, and a smooth-L1 `log1p(h)` term. Interface and predicted-consistency terms are also active. The port loss pools active module-port values within a batch; it does not directly optimize equal-case, per-M tail risk. The P2 port-global consistency term compares field temperature at predicted outside coordinates with final predicted port T, with gradients to both predictions. Teacher `T_outside`, interface `[T_surface, q_normal]`, and field-grid temperatures are separately defined targets; their locations should not be assumed identical.

The QE value gain and QM source gain have substantial endpoint target-error contributions at these weights; the QE score gain and source-local variation have smaller measured effects here. An endpoint ablation cannot prove a component's training role was unnecessary. All source controls and inherited \(\kappa\) therefore remain in the fresh candidate. In phase-scoped checks, every P2-only intervention left P0, P1, and final ports bitwise unchanged, while changing its P2 field where expected. All 140 measured variants preserved source incidence and validity masks. The difficult M=3 development case 0647 retains baseline final T-port relative L2 0.29128; QM identity changes it by −0.00527 but worsens its near-interface field error by +0.02333, and QE value identity worsens T port by +0.07557. These endpoint changes do not justify a port-tail repair by dropping a source control.

At exact e500, the 25 M=3 development cases have final T-port relative L2 mean/p90/max 0.13928/0.19995/0.29128 for Run 1507 versus 0.11915/0.16205/0.20088 for Run 1502. Case 0647 has the largest paired increase, +0.09040. M=3 contributes 15.7% of candidate pooled physical T-port SSE despite 27.8% of cases; higher-M improvements make all-M pooled SSE decrease even while equal-case mean relative L2 rises. This is an aggregation and risk mismatch to investigate, not evidence that direct port supervision was absent or implemented incorrectly.

## Bounded optimizer pilot and fresh-run selection

One Pilot A used the exact Run 1502 e50 shared state, a strict 280-to-275-state conversion, an empty/reset optimizer, and the same ordered train cases 0001/0309/0348/0355 (M=3/3/10/10) for 200 real predicted-port optimizer updates. It used no mature Run 1507 weights and consumed one of the three allowed pilot slots, 200 of 600 allowed updates, and 61.750 seconds of the three-GPU-hour pilot budget. All 200 recorded losses, sampled gradients, and parameter updates were finite. Total loss fell from 2.8590 at update 1 to 0.3699 at update 200; sampled preclip gradient norm fell from 28.71 to 12.35. Update work was 53.893 seconds, fixed full-grid panel evaluation 5.929 seconds, and peak process CUDA allocation 1.732 GB.

On that fixed panel, equal-case near-interface normalized relative L2 fell from 0.78362 before updates to 0.34466 after 200 updates, and physical final T-port relative L2 from 0.60702 to 0.11445. Each of the five physical field channels improved over the same span; for example temperature fell from 0.61280 to 0.25471 and velocity-u from 0.27241 to 0.12820. The M=3 absolute T-port error p90/max fell from 9.485/14.245 to 1.279/2.155. Interface q-normal relative L2 did not show a comparable gain. This is a small repeatedly trained panel, not a mature or independent performance estimate.

The abrupt mature e50 conversion has a large initial loss transient, but the inherited static reader learns through it within this 200-update pilot. The formal question is clean static learning from seed-0 initialization, which has no mature-model removal event. A parent-to-static warmup would change that question and require an additional architecture transition. No Pilot B or C is selected from these data. The one fresh candidate therefore uses the static source-conditioned reader from initialization with the inherited loss, optimizer, and predicted-port workflow; it will be reviewed at e50/e150 and stopped by e500.
