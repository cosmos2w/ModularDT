# HONF Run 1503-v3: converged, identity-preserving coalescence

The generated evidence paths and one-time diagnostic scripts cited here are retained locally and intentionally excluded from GitHub; the numerical findings needed to read this report are recorded below.

This experiment uses Run 1502's sparse-incidence physical model as its scientific base. The stopped Run 1504 (`1503-v2`) checkpoint is used only for frozen numerical diagnosis; the v3 candidate is a separately identified, fresh managed run. The v2 architecture and its fixed-64 solver remain available for historical checkpoint replay.

## Numerical planner and prelaunch decision

The v3 planner solves the existing v2 convex objective, including its implemented scale `lambda_b = eta * sigma`, with detached FP64 ADMM state on GPU 2. It stops each case when both standard primal and dual residual criteria pass, up to 512 iterations. Nonconverged cases retain singleton parent classes. The solver does not carry an autograd graph; physical gradients flow through the compact representation selected by its partition.

The plan's initial `eps_abs=1e-6`, `eps_rel=1e-5` stopped too early on real trained descriptors. A read-only replay of the Run 1504 e150 checkpoint covered cases 0273, 0686, 0281, 0277, and 0676 in P0/P1/P2. Those initial criteria matched the stable partition in only 6 of 15 phases. The adopted v3 numerical criteria, `eps_abs=1e-9` and `eps_rel=1e-8`, converged in all 15 phases within 84–243 iterations (median 121); the largest final primal/threshold and dual/threshold ratios were 0.9942 and 0.7224. All 15 partitions matched a stricter `1e-10/1e-9` replay and survived halving the class tolerance from `1e-5` to `5e-6`. Case 0281 P0 required 243 iterations. This adjustment sets the numerical criterion for the fresh run without changing the objective. The per-phase record is `diagnostics/generated/run1503_v3_preflight/run1504_e150_solver_stability.json`.

## Operator implementation and focused checks

The v3 architecture has a separate identifier, `converged_identity_preserving_coalescence_honf`. It preserves the v2 quotient's merged source incidence `Abar`, source-resolved control moment `B`, and multiplicity-correct sparsemax density. Accepted merged classes use an RMS-normalized barycenter of the original normalized query keys and source-measure centers recomputed from merged incidence. Singleton classes use the original parent keys and centers; an all-singleton phase uses the parent reader directly. The original fine source states, physical coordinates, and environmental K/V rows remain available.

Focused GPU 2 tests passed: 14 fusion tests, four historical v2 backend tests, and two v3 operator tests. The v3 checks cover nonzero-eta parent identity in logits, routing, source overlaps and moments, QM/QE, field, and first gradients; a mixed batch with a merged row and a singleton row containing an inactive proposal; and controlled quotient versus literal virtual expansion of QM/QE and gradients. These are controlled tests. Real-checkpoint optimizer, frozen replay, and formal-run results are reported separately below.

The disposable GPU 2 preflight strictly loaded the mature Run 1502 best-field weights into the v3 architecture at eta=0.5 and selected real case 0278 after scanning six development cases. Relative to the original stopped v2 output under the same frozen weights, the v3 field changed by relative L2 0.04557. Quotient parity and frozen parent perturbation are separate claims.

Two ordinary predicted-port optimizer steps used fresh disposable model states at absolute epoch 50: a mixed low-M batch of 48 cases with 1/2/3 active modules and an M=10 batch of 15 cases. Each step prepared P0/P1/P2 once, producing 144 and 45 *per-case* plan records respectively; all converged (no singleton fallback), with phase iteration medians 10–11 for low-M and 10 for M=10. ## Decision at the bounded stop

Run 1505 delivered real, stable accepted mergers and a same-stage full-grid fluid-field gain at e500, while preserving exact parent access for singleton classes and the conserved source-control quotient. It also retained a confirmed 3.05% narrow physical-design output jump, substantially worsened final port environment temperature across almost every case, worsened heat flux in most cases, and cost about 5x as much per complete application. The four solver fallbacks and the two strict-replay partition changes further limit numerical robustness claims. **Do not recommend a 5000-epoch continuation of this candidate as it stands.** The completed e500 checkpoint is a reproducible research endpoint; a later continuation decision would require a separate, explicit remedy and new evidence for the boundary, port-field fidelity, and execution cost. Historical runs and their checkpoints were left intact.

Final focused regression verification passed 71 tests covering fusion, v2/v3 routing and executor paths, configuration, and historical forward-upgrade behavior on the GPU-capable environment (`PYTHONPATH=src:Case_ThermalChannel/src:tests`, `pytest -q` on the seven relevant test modules). All changed Python files compiled, and `git diff --check` passed.
