# Finite observations for state and response learning

Two scenes can have different material regions and different observation rows. Predict the same joint physical fields for each scene, compare each prediction with its own saved reference, and summarize those residuals before comparing the scenes. This permits a material-temperature response term without claiming that material row 17 in one scene is the same physical object as row 17 in another. Existing native field supervision remains unchanged.

`honf_runtime.finite_observations` supplies the case-independent descriptors, sparse extraction and reductions. `honf_runtime.finite_observation_task` optionally attaches their scalar losses to an ordinary native task. It accepts any number of joint output fields and does not require a matched-row native population or uniform native sampling. Historical observation blocks and coupled-native response recipes retain their own meaning and recovery paths.

## Existing source rows and physical meaning

A `FiniteObservationFamily` declares a field component, units, positive TRAIN scale, physical support, common frame and time convention, linear extraction meaning, original source row IDs, coordinates, positive measures and saved references. The extraction retains every required dependency, including derivative and interpolation stencils. Two independently selected scene row sets may differ in size. Repeated coordinates retain their individual source rows and measures. A missing family is omitted, rather than given a zero target.

The default fixed panel selects at most 64 valid source rows uniformly without replacement, using only source validity and a reproducible seed. Keep that panel unchanged through the run. Normalize each scene's selected measures by their own finite sum. Normalize native family importances once across all configured families, retaining the weights of unavailable families in that denominator. Distinct physical supports sharing one output column remain separate families; a duplicate representation does not receive another complete family weight.

`AffineFrame` describes one input-derived frame shared across scenes. The primary summaries use the constant function and affine physical coordinates in this frame. If a family lacks that capability, it uses a constant summary and records the reduction explicitly. Coordinates outside the frame remain unclipped and are counted. The optional `tensor_hats` basis uses products of three one-dimensional hats; each hat retains the total family's finite measure normalization, including empty hats with an exact zero value.

For normalized residual `e = (prediction - reference) / TRAIN_scale` and finite measures `a`, the point anchor is the configured-weighted mean of `sum(a * e**2)` over scenes. A scene summary is `sum(a * basis * e)`. The contrast is the equal-pair mean of squared differences between compatible scene summaries, averaged over basis functions and combined with fixed family weights. Exclude pairs with no compatible family before fitting. Unpaired scenes still receive native and point-anchor supervision. No individual material-member correspondence is introduced.

These are exact objectives for the selected finite rows. They are not unbiased full-domain squared-integral estimates. Contrasts may be zero when both absolute fields share the same large error, or when local errors cancel in a summary. Retain point and native field errors, and compare fixed, independently seeded and complete-support summaries on already decoded review fields. Natural independently generated scene changes do not establish a fixed-control edit or a physical derivative.

## Case adapter interface

An observation factory registered through `register_observation_capability` returns the ordinary native model, provider and binding. The binding supplies `finite_observation_family_weights()`, `finite_observation_scene(case_id, count=64, seed=...)`, optional `finite_observation_frame()`, explicit TRAIN/validation pairs and their partition validation, and `field_request(model, case_id, dependencies)`. The last operation returns a prescribed scene, query carrier and joint-output affine scale/offset. Physical affine conversion happens before sparse extraction. `finite_observation_unsupported()` explains nonlinear quantities that remain outside this linear interface.

An optional `execute_finite_observation_dependencies` callback batches the extra queries and can reuse the current native batch's live prepared organization. It returns physical joint-field tensors and executed-work counters. It must preserve case order, original members, differentiability, query masks and complete dependencies. It must not detach the native forward path or cache learned preparations across optimizer updates. The generic fallback explicitly charges additional scene preparation and decoding.

Thermal implements fluid velocity, pressure, curl and temperature, material temperature, surface temperature, flux proxy and optional outside temperature. Material and surface rows belong to each scene's own source geometry. Module maxima and interface ratios are nonlinear and remain separate native/validation quantities. Fluid source weights are the saved dimensionless native row weights multiplied by cell area; they do not certify unbiased physical-domain quadrature. The adapter preserves saved reference precision and the maintained model's FP32 geometry/extraction arithmetic.

The seven-output software fixture supports ragged observations, nonuniform measures, absent families, and a finite-only binding without any `coupled_*` methods. Its optional weighted-with-replacement native sampler checks independence from the historical uniform native coupling requirement. It is a software test, not physical learning evidence.

## Objective, initialization and recovery

Use `training_profile: observation_response` and add `finite_observations` with `variant` equal to `disabled`, `anchors` or `contrasts`, `native_sampling` equal to `native` or the explicitly preserved `coupled_native` Thermal sampler, fixed probe count/seed/basis, pair-complete TRAIN calibration IDs, a metadata byte limit and a shared `epoch_zero_checkpoint`. Disabled runs execute no additional observation predictions. Anchor and contrast arms execute identical observations; only the contrast scalar differs.

At the common fresh epoch-zero state, measure both-reader native, anchor and contrast gradient norms on the declared input-selected TRAIN panel. The fixed initial auxiliary gradient RMS ratios are 0.10 and 0.05 of native. Share the resulting anchor coefficient between both probe arms. Preserve initialized parameters, optimizer, normalization, RNG, sampler/provider state and organization clocks during calibration. Apply `min(absolute_epoch / 50, 1)` from the first training epoch. These are initial settings, not promises about later gradient influence or field accuracy.

The update is one ordinary scalar backward through the native, anchor and contrast paths. It has no projected auxiliary gradient, parameter mask, second VJP, teacher or response prediction head. The old all-parameter coupled recipe intentionally retains its native-priority two-gradient composition; comparing it with finite probes compares complete recipes.

`tools/observation_response_prepare.py --fresh-epoch-zero --recipe RECIPE --output ZERO_STATE --device DEVICE` saves one actual common initial state. `tools/relation_anchored_train.py fit --recipe RECIPE --output RUN --stop-after EPOCH --device DEVICE` starts a fresh arm from that state. Resume the same saved recipe and run with `--resume latest`; review stops do not restart or compress the absolute schedule. GPU selection belongs in runtime configuration.

Source indices, weights, extraction maps and actual basis/frame capability are saved once in the shared zero state's companion observation JSON. Each run's `configs/finite_observation_objective.json` references it and records the objective/calibration. Checkpoints retain recovery counters and coefficients rather than duplicating these source maps or numerical histories. Ordinary resume compares semantic definitions, preserves saved CSV/loss accumulation order, and appends without migrating histories.

`tools/verify_coupled_native_recovery.py --recipe RECIPE --output-root EMPTY_ROOT --device DEVICE` checks uninterrupted training against a real checkpoint interruption and fresh-process saved-config reload/resume. It checks tensors, optimizer, RNG, sampler/provider, reader state, finite source maps/calibration, recorded values/order and curve artifacts. Timing and disposable cache-build counters are explicitly excluded from numerical equality. Use this qualification within an authorized experiment and its epoch/storage budget.

## Checkpoint gradient audit

`python tools/finite_observation_gradient_audit.py --checkpoint CHECKPOINT --panels MATCHED_PANELS --stage development --device DEVICE --output AUDIT_JSON` measures the saved checkpoint on the declared pair-complete TRAIN150 review panel; use `--stage formal` for TRAIN600. The panels contain 16 of 150 or 60 of 600 cases, respectively. The native sampling stream is fixed to epoch 1 for matched reviews, while the organization clock and finite-loss ramp use the checkpoint's actual epoch. This audit reconstructs ordinary native draws with the same native marginal and objective; it does not replay the pair-coupled draws used in training. Full and restricted readers are measured separately.

For each physical family, the raw contrast gradient is the unweighted gradient of its scene-summary error, averaged over the fixed eligible-pair count. Its weighted contribution additionally applies that family's configured weight divided by the sum of all configured weights, including weights of absent families. Norms are reported for all trainable parameters, exclusive organization parameters, and the remaining content and output parameters. The reported total contrast norm comes from the sum of weighted gradient vectors; it is not the sum of family norms.

The audit also reports native, anchor and total contrast gradients, the saved epoch-zero coefficients, and their checkpoint-epoch ramp. Enabled terms have effective scaled norms; disabled terms remain prospective measurements, with a prospective scale only when the checkpoint contains the saved calibration. Other training losses, including legacy response objectives, are excluded from the combined native-plus-finite norm. The audit does not recalibrate, update an optimizer or change the model, provider state, random generators or clocks. These panel gradients describe training-signal reach, not a fixed-control physical response or a learning result.

## Cost and evaluation boundaries

Record real and padded query slots, dependencies, preparation reuse, original-member score/value work, complete process time and peak memory. Fewer VJPs or shared preparation alone does not establish a measured speedup. Keep activation checkpointing and configured query tiling, and compare complete epochs on the same device. The probe metadata cache is immutable and bounded independently of any inherited native-plan cache.

Evaluate matched approximately 10% case panels by default and both readers at declared reviews. Keep full valid physical support within selected cases, absolute errors at both edited states, predicted-change error, direction/amplitude and zero-change references. An existing saved request requires its entire candidate board. Preserve source TRAIN/validation/TEST meanings and historical exposure. Native accuracy, natural-scene response, specified edits, organization interventions and physical design validation are separate conclusions.

`tools/finite_observation_evaluate.py --checkpoint CHECKPOINT --panels MATCHED_PANELS --stage development --device DEVICE --output REVIEW_JSON` reuses one complete within-case prediction per reader for native fields, natural field-change errors/direction/amplitude, and fixed, independently seeded and complete-source observation summaries. Use `--stage formal` for the saved TRAIN600 panel or `--assessment9` for the declared exposed held-out panel. Near-null reference or predicted changes retain raw errors and explicit unavailable ratios/cosines. The command omits the unrelated historical three-scene assignment diagnostic. It validates saved family weights, frame, physical scales and offsets; its probe-recipe agreement flag does not independently compare literal saved row and extraction maps.

Loss histories use the shared CSV contract, explicit ordered definitions and equal-sized total/component panels, first available curves and ten-epoch refreshes. Keep full history and declared recovery checkpoints. A measured losing recipe can be closed while retaining the useful general interface or execution improvement.
