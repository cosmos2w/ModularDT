# Thermal organization response probe

`channelthermal.response_control.transfer_probe` provides the R15-6 numerical probe. `atlas_edits(path, beta=...)` reads the existing response atlas and derives each of its eight geometry edits from original module IDs and saved positions, together with physical smooth-material-temperature and pressure-drop changes. Set beta to the reciprocal of the frozen evaluator's declared temperature smoothing scale, and use the same native material receiver definition for predictions and references. Receiver-level field responses remain available through `ResponseStencil.finite_change`; its original receiver IDs and masks distinguish module-attached and Eulerian measurements.

Prepare each layout afresh in full mode and retain actual query M coefficients, objective derivatives, anchor indices and weights, E measures, full E-directory M columns, and named final-cycle MM and E←M gates. Pass these ID-aligned arrays to `organization_features`. Missing trace components are unavailable evidence, not zero-valued features. If a trace component is unavailable across the comparison, use `organization_slots` to remove that feature from every arm before evaluating outcomes. Save the full traces and the bijective module-slot permutation; use the same permutation for all relational/query inputs within each layout. Do not apply it to the model state.

`feature_row` declares 24 scalar features. Supply six prescribed-context and six direct-field forward slots in the order in `FEATURES`; derivatives must be dotted with the actual edit. Construct a no-organization control by masking the final six slots and a permuted control using the same features extracted with a consistent permutation. `fit_three_arms` uses FIT families 0001, 0318, 0333 and 0348 only, with FIT-only standardization and fixed ridge penalty; it charges three calibration epochs. `evaluate_probe` reports per-family physical and FIT-scaled errors, ordering and top-k regret. `useful_transfer` applies the four-family DEV criterion and requires a separately recorded pressure-usability decision. Development families 0304, 0320, 0335 and 0350 are exposed and development-selected, not independent TEST.

Only after this criterion passes, `request_distribution` scores the eight saved edits and exact no-op for FIT-derived cooling bands and surrogate-baseline pressure limits. It reports probabilities and retrospective physical regret from saved physical changes. Compare request preferences on FIT before describing the output as useful conditioning. The function does not fit a generator or authorize new solves. Features, trace extraction and elapsed evaluation costs must be retained with any experiment result.

The maintained driver `tools/thermal_organization_transfer_probe.py --checkpoint CHECKPOINT --atlas ATLAS_DIRECTORY --output NEW_DIRECTORY --device cuda:0` evaluates eight frozen baseline layouts, extracts full-mode material-objective query traces and design derivatives, and performs the three FIT calibrations. It saves feature arrays, per-layout traces and permutations, probe coefficients and predictions, DEV summaries, and initial/final FIT and DEV loss curves. `--trace-only` saves the full and restricted M/E directories and full-mode material-objective M/E query coefficients without calibration. Pressure directional derivatives are included in the features; pressure-objective query contributions require separate extraction. Configure the device by physical UUID before invoking the command, and verify storage and device ownership as required by the project protocol.

The driver detects R15-6 port-response checkpoint recipes and uses their dedicated loader, while historical R14 checkpoints use the contextual loader. Each saved pressure trace contains the signed derivatives at the contributing native pressure receivers and at their underlying native-union query points, together with full-mode M/E access coefficients. These signed pressure derivatives are retained for interpretation and are not substituted for the nonnegative material-objective weights in the feature vector. The loss PDF includes FIT MSE plus the actual ridge penalty, FIT MSE alone, and exposed DEV MSE. `request_distributions` accepts one shared surrogate baseline pressure and a common physical catalogue for all arms.
