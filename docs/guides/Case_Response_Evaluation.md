# Case response evaluation

A finite response is the difference between two complete case executions. Rebuild the scene, native receivers, contextual organization and query access for each changed design; keep original member IDs and prescribed controls. `honf_runtime.response_evaluation` supplies in-memory mechanics for the relation-anchored core and for the Thermal native adapter. Callers select inputs, establish case-specific legality and match references; the evaluator does not establish physical accuracy. Instrumented timings include tracing, and do not replace complete uninstrumented runtime measurements.

## Available references

Thermal's existing saved physical response atlas is at `HONF_Proj/diagnostics/generated/interactions/physical_response_atlas_20260926/families/train_<ID>_responses.npz`. IDs 0001, 0318, 0333 and 0348 are the existing TRAIN geometry-family set; 0304, 0320, 0335 and 0350 are held out from the earlier response-fit cohort but also carry original source TRAIN provenance. They are response-validation families, not an independently sourced validation or TEST partition. The files contain solver-produced baseline and finite control variants, including single geometry changes `i_minus`, `i_plus`, `j_minus`, `j_plus`, mixed corners `mm`, `mp`, `pm`, `pp`, and heat-transfer plus/minus controls. Their original module IDs, exact perturbations and partition metadata are read by `channelthermal.interaction_evidence.response_atlas`; use those recorded controls rather than assuming a common step size. Historical zero-heat controls, when present, are distinct from a heat change that leaves the obstacle present.

For matching, use the saved common-valid Eulerian coordinates and masks for fluid fields, the same original-module 64-angle surface receivers for interface temperature and heat-flux proxy, and the same original-module local material points and masks for solid temperature. Surface and local receivers move with their module; fixed Eulerian receivers do not. Thermal reference physics and proxy limitations are described in `Case_ThermalChannel/Dataset/PHYSICS_AND_DATA.md`; these data are not independent conjugate-CFD measurements. Availability of one atlas family does not provide arbitrary layout, heat, or mixed-control reference coverage. `honf_runtime.contextual_frontier_responses` provides an existing atlas evaluation and records its cohort and support conventions.

Wind's input rows and native velocity targets are described in `Case_WindFarm/Dataset/PHYSICS_AND_DATA.md`. Rows for the same `layout_index` describe categorical wind-direction conditions; neighboring layouts must not be treated as a paired finite-response reference without matching their input changes, fixed controls, receiver coordinates and valid support. A matched Wind layout-response family has not been established by this inventory. Do not access locked TEST data to fill the gap.

## Measurement specification for R15-4

Select cases from inputs and preserve the existing split and normalization. For every matched finite perturbation, report the per-field reference and prediction response error on their common physical support, reference and predicted amplitude, and sign agreement where the reference amplitude is meaningful. State reference provenance, units, perturbation, mask and unavailable combinations. Report fixed-space fluid receivers and moving-module receivers separately, and mixed perturbations separately from single changes. When references are absent, report numerical/model sensitivity only.

Compare a full layout-to-native-objective autograd directional derivative with central finite differences at multiple perturbation magnitudes while preserving fixed support, and separately measure behavior as masks, cover support or routing change. Compare applied directional contextual relations with explicit stage provenance and original-ID alignment, directory membership/weights and query contributions before and after perturbation. Controlled relation interventions must identify the actual executed stage and quantify field and objective changes; their results establish dependence of this model execution, not physical causality. Report selected records, executed pair work, preparation and complete runtime separately, including full-access fallbacks. Evaluate objective and constraint ranking only against matched physical references and case-specific spacing, geometry and feasibility rules. Derivative consistency, response accuracy, organized dependence and verified physical design quality are separate outcomes.
