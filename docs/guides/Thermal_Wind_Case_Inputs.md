# Thermal and Wind case inputs

The case adapters own physical inputs, coordinates, measures, normalization and native extraction. The current public `relation_anchored` constructor selects the detail-preserving joint-field core. Saved models retain their original schemas and case loaders; a family name does not make historical architectures interchangeable. See [case integration](../case_plugin.md) for the shared contract.

| Quantity | Thermal | Wind |
| --- | --- | --- |
| Original M records | Present circular modules, with original member IDs and a presence mask; padded slots carry no contribution. | Row-specific turbine centers and original turbine IDs, with presence masks. Preserve the direction row's own geometry. |
| Prescribed M inputs | Center, radius, heat and declared material properties; geometry/material/heat vary only within the dataset's supported semantics. | Center in rotor diameters, radius `0.5D`, hub height `0.875D`; the latter two are constant in the current dataset. There is no supported yaw or turbine-material control. |
| Prescribed context | Domain, inlet/Reynolds and saved material/diffusivity context, as encoded by the Thermal reader. | Categorical direction 270/285/300 degrees, reference speed 9 m/s, turbine count and exact row-specific cell-center support. A direction category does not establish a continuous meteorological-angle convention. |
| E representation | The current baseline uses `24x8` geometry-owned environment records. Retain positive physical measure, coordinates and IDs. | The fresh adapter starts with `4x4x4` centers over the prescribed support box. The configurable lattice preserves that domain and its total represented volume in `D^3`; changing its shape does not create new CFD boundary data. |
| Queries and physical outputs | Joint `[u,v,p,T]`; native extraction also derives the historical vorticity observable and module/interface temperatures and flux proxy. | Joint `[Ux,Uy,Uz]` at native cell centers; inverse normalization and any saved TRAIN-fitted vertical-profile residual transform return m/s. |
| Units and masks | Benchmark-native coordinates, temperature and flux units; do not infer SI units without provenance. Use the actual fluid, solid-disk, presence and interface-validity masks. | `D=80 m`; coordinates in `D`, native velocity in m/s. Full-volume fields use their exact ragged cell-center support; compact fields require their stored validity masks. Rotor masks are not validity masks. |
| Membership | Reuse the selected recipe's existing input-only manifest, TRAIN600 or declared subset, and checkpoint-owned TRAIN normalization. Historical exposed validation is not an independent locked TEST result. | Reuse the saved layout-group split: all direction rows for a `layout_index` stay together. Reuse its TRAIN-fitted normalizer/profile; never refit from the mechanics panel. |
| Reference limits | Analytic-wake velocity/pressure plus a shared thermal grid, not conjugate Navier–Stokes CFD. | Existing steady CFD exports. Observed cell-center support does not identify physical face boundary conditions. |

The detailed source schemas remain in [Thermal physics and data](../../Case_ThermalChannel/Dataset/PHYSICS_AND_DATA.md) and [Wind physics and data](../../Case_WindFarm/Dataset/PHYSICS_AND_DATA.md). Solved outside/interface temperatures, targets, wake-loss labels and velocity arrays are observations, not scene inputs. Geometry-distance features provide geometric information, not unknown boundary values.

## Differentiable Wind design input

[`WindRelationAnchoredAdapter`](../../Case_WindFarm/src/windfarm/relation_anchored.py) accepts a live torch layout tensor in `make_scene(case, module_centers=...)`, builds geometry-only E records, and attaches continuous trilinear E coverage in `make_query`. The supported design variables are horizontal x/y coordinates; prescribed hub heights remain fixed. Preserve original IDs through `module_ids=...` in `make_scene` or `forward` when permuting all member-indexed inputs. Build all affected scene, query and organization state again for each perturbed layout. Keep the support and prescribed context fixed for a layout experiment. Native NumPy/mmap I/O remains unchanged; the design tensor passed to the adapter is the variable differentiated through the joint prediction and native transform.

The cover uses the actual E coordinate-to-slot map, including after a consistent E permutation. Weights are nonnegative and sum to one for active queries. Outer half-cells clamp to their nearest center; active queries outside the declared support are rejected. Singleton lattice axes contribute only once. The shared core admits eight cover addresses in 3-D while preserving the historical four-address allowance elsewhere. These mechanics do not establish field accuracy or physically correct design sensitivities for initialized Wind weights.

## Frozen Thermal local operator

The preserved Stage-A interface takes seven parameters, ordered `[q_internal, solid_k, solid_alpha, h_mean, h_std, T_env_mean, T_env_std]`, and five angular port features `[theta, cos(theta), sin(theta), T_env, h]`. The global-alignment reader populates the first column from its heat input. It returns masked solid temperatures, interface `[T_surface,q_normal]` and a latent. Load the actual checkpoint with its embedded configuration and normalizer through the existing strict loader. A neighboring configuration or a directory name is insufficient evidence of checkpoint provenance.

Teacher ports use solved `T_outside` and `h_effective`, so their replay is oracle-conditioned. The flux target is a sampled shared-grid proxy. Its effective coefficient is a temperature-jump ratio with denominator, clipping and mask semantics; because the flux itself uses that jump, this ratio is not an independent convection estimate.

The case-owned port interface takes prescribed module properties plus predictions from the current organized joint context, recomputes all four port summary columns from those same predicted ports using `update_local_module_params_from_ports`, and makes one batched frozen local call over present modules. Its implementation does not establish a trained or accurate port estimator; assess each saved lineage against direct joint and oracle-conditioned readouts as described in [case relation-anchored training](Case_Relation_Anchored_Training.md). Measure interface consistency before adopting local outputs. Latent feedback and repeated organization preparation require separate evidence.
